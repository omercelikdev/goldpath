# Upgrading to 0.1.0-preview.5

**One migration to generate; no breaking API changes.**

The train adds the scheduling surface (admin contract Revision R2) and fixes two things a
single-app adopter meets on their first screen.

## The one step: a migration

`GoldpathJobRun` gains a nullable `TriggeredBy` column (`Scheduled` | `Manual` | `Rerun` |
`Replay` — who put the run on the schedule). After taking the train:

```bash
goldpath db add AddJobTriggeredBy
```

Existing rows keep `null`, which the console shows as "not recorded" — it will not guess
about runs from before the column existed. Until the migration is applied, reading runs
fails with a missing-column error, so generate it in the same change that bumps the pins.

## What you get without doing anything

- **The console's Runs section becomes the scheduling surface**: fleet state (with the
  durable `pause-all`), jobs with their triggers (add/remove/reschedule, read-only data
  map), calendars, and a history filterable by state and date. Runtime job authoring
  remains impossible by design (ADR-0001) — scheduling is configuration, composition is
  the manifest's.
- **A paused job now looks paused.** The console had been reading fields the contract
  never sent; a paused job was indistinguishable from a running one on screen.
- **No more false registry warning.** An app that configures no console services
  previously greeted its operator with "the service registry lists no service with a
  name" — the unconfigured registry now answers 404 and the console reads it, silently,
  as "this service only".
- **Multi-tenant apps: the console page is exempt out of the box.** `/goldpath/console`
  ships in the default tenancy exempt paths, so the page loads without a tenant header
  (the admin surfaces behind it stay scoped by R1 exactly as before). If you added the
  path to `ExemptPaths` yourself as a workaround, you can drop it.
