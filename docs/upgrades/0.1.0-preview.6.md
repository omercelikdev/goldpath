## Campaign revision R1 — one migration

R1 adds three columns to `GoldpathCampaigns` (`ExcludedDays`, `EndDate`, `MaxAttempts`)
and one to `GoldpathCampaignItems` (`Attempts`). After updating the packages:

```bash
goldpath db add CampaignR1
goldpath check
```

Nothing else changes for existing campaigns: the defaults reproduce today's behavior
exactly (`ExcludedDays` empty, `EndDate` null, `MaxAttempts` 1, `GlobalTps` off). The
new dials are live-adjustable through the throttle verb like the old ones; two new
enum values appear (`GoldpathCampaignState.ExpiredIncomplete`,
`GoldpathCampaignItemState.AwaitingRetry`) — exhaustive switches over those enums gain
a case.

`GoldpathCampaignOptions.GlobalTps` (per-process ceiling across ALL running campaigns)
is opt-in at composition:

```csharp
builder.AddGoldpathCampaign<WebApplicationBuilder, AppDb>(campaign =>
{
    campaign.GlobalTps = 500;   // platform protection; null (default) = off
    // …
});
```

## Admin contract Revision R3 — repeatable filters

Already on main (2026-08-02): list filters may repeat (`?state=a&state=b`, OR within a
filter, filters AND together). Additive — nothing an R2 client sends changes meaning.
The campaign list/DTO also carries the R1 policy fields (`excludedDays`, `endDate`,
`maxAttempts`), and the throttle verb accepts them plus `clearExcludedDays` /
`clearEndDate`.
