# Upgrading to 0.1.0-preview.7

**One migration to generate; no breaking API changes.** Everything else on this train is
additive: two new packages, a new SDK package, new CLI verbs, and a console module that
lights only when the app composes it.

## Package document columns — one migration

Ten package columns that hold DOCUMENTS (approval payloads and baselines, audit values,
erasure evidence, notification bodies) now declare `HasMaxLength(-1)` instead of
inheriting the conventions' 256-character default — which refused or silently truncated
real content on every conventions-shaped host (found live as a 22001 by the
qorpe.apiPortal pilot). Bounded human-text columns (decision reasons, erasure detail)
state their bound on purpose. After updating the packages:

```bash
goldpath db add PackageDocumentColumns
goldpath check
```

The migration widens columns only — no data moves, nothing shrinks, existing rows are
untouched.

## New on the train (adopt when you want them)

- **`Goldpath.Approvals`** and **`Goldpath.FileExchange`** reach nuget for the first
  time. Turning one on is the standard composition ride: `goldpath add feature
  approvals` / `fileexchange` (manifest + wiring + model contribution + `goldpath db
  add`). Nothing exists in your app until you do.
- **Approvals in the console.** If the app composes approvals AND maps
  `MapGoldpathApprovalsAdmin()`, the console discovers the surface and the sixth module
  appears — worklist, quorum numbers, trail, decide verbs. No mapping, no module.
- **`Goldpath.Sdk`** arrives as a dependency of the admin surfaces; you take it
  transitively. Direct reference is only for building your OWN admin surface on the ops
  floor (`AdminSurfaceGuard`, `AdminPaging`, `AdminTenantScope`).
- **CLI verbs**: `goldpath new` (service, gateway, bare wizard), `goldpath init`,
  `goldpath discover`, `goldpath export compose`, `--layout clean-architecture`.

## ServiceDefaults now registers the discovery core (#197)

`AddGoldpathServiceDefaults()` calls `AddServiceDiscovery()` itself, so typed clients
using the per-client handler resolve without composing the core by hand. If you added
`builder.Services.AddServiceDiscovery()` as a workaround, delete it — the call is
idempotent, so leaving it is harmless, but it no longer earns its line.

## Template pins

Generated apps pin Mediant 1.4.1 (the train's own build pin). If you generated an app
from an earlier template and bump it to this train by hand, raise your `Mediant` /
`Mediant.AspNetCore` pins to 1.4.1 too — the older 1.4.0 pin under this train's
packages is an NU1605 downgrade at restore.
